DTLcompare — Guide utilisateur

Guide de comparaison de deux snapshots DTLknowsWhy afin d’expliquer pourquoi un accès fonctionne depuis un poste et échoue depuis un autre.

DiagnosticSnapshots JSONHTML / TXT / JSON

Objectif

DTLcompare aide à transformer deux diagnostics bruts en une conclusion lisible : causes probables, causes éliminées, preuves et pistes de remédiation.

Préparer les deux snapshots

  1. Produire un snapshot depuis le poste où l’accès fonctionne.
  2. Produire un snapshot depuis le poste où l’accès échoue.
  3. Conserver les deux fichiers JSON dans un dossier de travail commun.
  4. Identifier clairement lequel est le cas « OK » et lequel est le cas « KO ».
L’ordre est important : le premier fichier représente le scénario qui fonctionne, le second le scénario qui échoue.

Lancer une comparaison

python comparative_analysis.py ok.json ko.json

Le script génère les rapports dans le dossier courant et affiche une synthèse dans la console.

Rapports produits

Rapport HTML

Document principal pour la lecture et le partage avec une équipe support ou infrastructure.

Rapport texte

Résumé lisible rapidement, pratique pour copier une conclusion dans un ticket.

Rapport JSON

Version structurée destinée à l’archivage ou à un traitement automatisé.

Lire l’analyse

  • Commencer par la conclusion humaine.
  • Lire les causes probables classées par score.
  • Vérifier les causes éliminées pour éviter les fausses pistes.
  • Contrôler les preuves utilisées dans chaque constat.

Bonnes pratiques

  • Comparer deux tests réalisés vers la même cible.
  • Éviter de mélanger des snapshots collectés à des moments trop éloignés.
  • Conserver les rapports avec les snapshots d’origine.
  • Relancer une comparaison après correction pour confirmer la disparition d’une cause.
